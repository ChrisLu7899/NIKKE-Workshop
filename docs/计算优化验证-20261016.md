# 计算优化验证（2026-10-16）

开发验证基线为 1.0.14，现纳入 1.0.15 发布。本次实现以当前源码为基线，参考用户提供的朋友优化交接说明与 1.0.12 安装包中的优化思路；未用旧安装包覆盖当前版本，也未引入新的依赖。

## 实现边界

- `engine.js`：共享等价动作的转移数组，注册状态时直接使用索引；按权重聚合非目标词条，逐次扣减数量，保持不放回抽样；模型内缓存档位概率。
- `calculationRules.js`：将转移编译为类型数组，以正成本方程 `c = Σ p·max(V−v, 0)` 迭代接受阈值，最多八轮；非标准输入或未收敛时回退原排序算法。最终策略仍用原算法生成明确的接受集合。
- 全局缓存包含规则、目标顺序、完整抽象初始状态，不按装备编号隔离相同问题，也不把不同物理槽位/锁定/强制保留混为一谈。缓存仅在本次全局任务内存活。
- 候选阶段不生成最终策略树。选定方案重新精算并保留完整决策树，显示与导出接口不变。
- 剪枝只在已有三个完整候选时启动，且部分成本严格大于第三名成本加数值容差才中止；剩余装备成本非负，因此不会移除可能进入搜索种子集合的方案。原全局候选生成、搜索宽度与轮数不变，不把有限候选搜索称为穷举证明。
- `calculator.worker.js`、`workerClient.js`、页面任务调度均保持原样。单装备、批量及全局任务继续完整运行在现有 Worker 中。

## 原版逐状态对比

以本次修改前的源码独立运行作为参考，按状态键而非数组下标匹配。

- 12 个单件场景：两个规则各覆盖单目标、G25、已达标、强制保留非目标、三目标最低档、三目标第 10 档。
- 每个场景核对期望、首步动作、状态数、每个状态的价值与动作策略；全部一致（数值容差 1e-7，实际最大状态差异小于 7e-13）。
- 96 组名称/数值转移对比：两个规则、1/5/6/10/11/15 档、锁定与强制保留、不同锁掩码；结果集合与概率一致，最大概率差异约 6.7e-16。
- 两套规则下，四装备单条件、两个不同装备双条件、四装备已满足目标三类全局案例均与原版目标分配及期望一致。已满足案例原版精算 32 个候选，优化后精算 21 个、提前排除 11 个，胜出方案相同。

## 性能样本

本机 Node 同进程分别执行修改前和修改后的纯计算核心，包含最终策略生成，不含浏览器绘制与 Worker 消息传输。以下为验证过程中的单次样本，不是普遍加速承诺。

| 案例 | 规则 | 原版 | 优化后 |
| --- | --- | ---: | ---: |
| G25：锁定攻击，补优越 | 旧 | 202 ms | 47 ms |
| G25：锁定攻击，补优越 | 新 | 337 ms | 44 ms |
| 三目标第 10 档，3913 状态 | 旧 | 9624 ms | 5987 ms |
| 三目标第 10 档，3913 状态 | 新 | 43555 ms | 2221 ms |
| 两件不同装备、攻击与优越双条件全局分配 | 旧 | 6602 ms | 1304 ms |
| 两件不同装备、攻击与优越双条件全局分配 | 新 | 8263 ms | 985 ms |

高复杂度目标仍可能计算较久，原 24000 状态及收敛限制不变。不同盘面、运行时预热与设备性能会改变耗时。

## 持续回归

新增 `tests/calculator-optimization.test.mjs`，包含 20000 组固定种子的加权动作对照、异常值/更新后的价值数组、独立逐词条枚举概率、缓存键隔离、并列剪枝及原版全局分配基线。既有 Worker 基线改为仅对期望数值使用 1e-7 容差，首步、状态数与迭代数仍严格对照。
