## 当前行为

- 同步保存四部位 `head/torso/arm/leg_equip_tid`、`*_equip_lv`、`*_equip_corporation_type`，与改造词条分离。沿用原同步端点、请求预算和原子提交。
- 本地模型 `equipmentMetadata` 固定四槽，顺序为头、身躯、臂、腿。每槽 `{tid, level, corporationType}`；`null` 表示未知，`tid:0` 明确表示未装备，强化 0 是有效值。
- 124 条官方装备记录按 ID 精确对应部位、职业、阶级和 72 个资源 ID。T1/T2、T3/T4、T5/T6、T7/T8 共图；阶级不能从图名猜测。表中另有 4 条 T9/All 占位 ID 共用 `_t9_3`，仍按 T9 处理，不声称已在真实账号验证。
- 新增 60 张普通装备原图，复用既有 12 张 T10 原图。普通装备显示 T 阶级与中性边框，不加紫色改造徽章。企业信息来自装备本身，不从角色企业猜；T1～T9 企业徽章是原始 glyph 的独立 UI 叠层。
- 未装备显示文字占位；未知 ID、错部位或加载失败不回退为默认 T10。旧记录只有真实改造词条且职业明确时，保留 T10 显示兼容。
- 同步确认换装或卸下后清除原 T10 词条；同步漏字段不随意清空已知装备信息。保存、刷新、本地图鉴与统一角色快照保留装备身份。
- 普通装备不允许写入改造词条；冲突导入会明确报错而非静默保存错误数据。确认的 T10 OCR 导入同时更新对应部位身份，但不编造强化等级。阿卡仍未新增普通装备 ID 映射；与现有普通装备身份冲突的词条导入需先重新同步或使用确认的 T10 截图。
- Excel 装备表新增“装备编号／强化等级／装备企业类型”三列；旧文件缺列时保留已有信息，新文件空白为未知。非法编号、重复槽位等拒绝覆盖该角色。

旧版本同步缓存没有保存的字段无法追溯还原。安装验收目录最新版后，需重新同步一次 Blablalink。未访问真实用户账号，本次使用官方静态表与隔离合成数据验证，不声称确认了用户当前账号具体有哪些普通装备。

## 素材与后续 OCR 接口

唯一素材输入：素材库正式 `output/character_card_ui_equipment-standard`，以及既有正式 `character_card_ui_equipment`。Workshop 不访问原始游戏目录或解包缓存。

`node scripts/sync-equipment-catalog.mjs` 完整校验晋级状态、逐图复核 SHA、官方表/目录 SHA、每张 PNG 及旧素材复用关系后生成文件；`--check` 为只读全量核验。正式输入覆盖数量变更时主动失败，要求复核新批次，避免静默漏图。

未来 OCR 共用 `src/data/equipmentCatalog.json` 和 `equipmentCatalog.js`。先识别部位、职业、候选外观，再结合可见阶级标记确定 ID；T1/T2 等同图不能仅靠模板唯一判定。没有足够证据时保留候选和未知状态，不写入猜测 ID。当前 OCR 的非 T10 识别任务仍未完成。
