# NIKKE Workshop 数据获取与请求安全说明

> 适用版本：`NIKKE Workshop 1.0.3`
> 整理日期：2026-08-19

## 1. 结论

当前“获取妮姬数据”不会按照全图鉴约 199 名妮姬逐个发送网络请求。

完整图鉴只用于建立本地输出模板。正式获取时，程序先通过一次
`GetUserCharacters` 取得账号已拥有角色，再取本地图鉴与已拥有角色的交集，
最后把全部交集 `name_code` 放进一次 `GetUserCharacterDetails` POST 中。

因此，已拥有角色数量主要影响一个详情请求的请求体和响应体大小，不会让 HTTP
请求数随角色数量线性增长。把详情拆成逐角色请求反而会显著增加请求数量，本版
没有采用这种做法。

## 2. 正常单账号请求规模

在 Cookie 有效并能直接取得 `area_id` 时，常见流程如下：

| 阶段 | 接口 | 常见次数 |
| --- | --- | ---: |
| 登录态和区域确认 | `GetUserGamePlayerInfo` | 1 |
| 昵称补充 | `GetUserProfileBasicInfo` | 1 |
| 前哨和同步器 | `GetUserProfileOutpostInfo` | 1 |
| 主线进度 | `GetUserProfileBasicInfo` | 1 |
| 已拥有角色 | `GetUserCharacters` | 1 |
| 已拥有角色详情、技能、装备和词条 | `GetUserCharacterDetails` | 1 |

正常情况约为 6 次账号 API 请求，另有主线目录、妮姬目录和等级曲线等静态资源
请求；静态资源具有本地缓存或打包快照，不会按角色重复请求。

手动指定 `area_id` 时，登录态通过 `CheckLogin` 验证，常见账号 API 请求约 5 次。

## 3. 可能增加请求的情况

- Cookie 有效，但玩家资料接口没有返回 `area_id`：会尝试自动区域识别。
- 全球服区域识别最多验证 `84`、`82` 两个候选；港澳台服只验证 `91`。
- 角色列表或详情出现可疑的异常空响应：本版最多等待 2.5 秒后整轮重试一次。
- 用户点击“登录”会在新标签页打开 Blablalink；完成登录后，“保存/更新 COOKIE”会读取当前 Blablalink 会话并更新本地 Cookie。

## 4. 当前请求保护

- 单账号串行：历史多账号数据即使仍存在，也不再以每批 5 个账号并发抓取。
- 运行中去重：同一页面已有数据任务运行时，重复点击不会再启动第二轮请求。
- 完整抓取冷却：一轮结束后 60 秒内不允许再次启动完整抓取。
- 有界空数据重试：整轮重试从最多 3 次降为最多 2 次。
- 批量详情保留：所有已拥有角色继续使用一次详情请求，不进行逐角色拆分。
- 获取后复用：下载 Excel 和进入计算器继续复用已缓存结果，不会重新抓取。
- 持久化轻量熔断：429 默认暂停 30 分钟并尊重更长的 `Retry-After`；403 暂停 60 分钟；异常空数据暂停 15 分钟；网络或 5xx 连续失败两轮后暂停 10 分钟。
- 自动恢复：暂停到期后只允许一次恢复测试；成功即复位，失败则按对应类型重新暂停。
- 误判控制：账号、Cookie、密码和 `area_id` 等配置错误不计入熔断。
- 本地功能不中断：熔断只限制新的同步请求，不限制下载已缓存数据或使用计算器。

## 5. 关于“是否会触发反爬虫”

从请求数量看，正常单账号手动获取一次的请求规模不大；当前实现也没有高并发、
逐角色循环或后台定时抓取。因此，仅从技术负载推断，风险明显低于逐角色爬虫。

但无法保证“不会触发”。Blablalink 没有公开这些接口的限流阈值、风控规则或
第三方调用授权说明，服务端也可以随时按账号、Cookie、IP、频率、行为模式或
其他信号调整策略。连续手动点击、批量账号、高频区域探测和不断重试都会增加
风险。

此外，[NIKKE 官方服务条款](https://nikke-en.com/termsofservice/children/en.html)
对未授权第三方程序收集游戏信息、自动化交互和数据挖掘有明确限制。降低请求
频率只能减少技术负载，不能等同于获得官方授权，也不能消除账号、服务条款或
接口变更风险。发布前应在 README 和免责声明中清楚说明这些边界。

## 6. 使用建议

- 只在需要刷新账号数据时手动获取，不要连续点击。
- 获取成功后直接使用本地的下载和计算器功能。
- 优先保存有效的 `area_id`，避免每次都执行候选区域探测。
- 不要把当前版本改造成定时后台抓取或大规模账号并发工具。
- 遇到 `429`、`403`、`5xx` 或反复空数据时停止重试，稍后再操作。

## 7. 代码边界

- `src/domain/account.js`：账号和 Cookie 内部数据契约。
- `src/domain/characterAccountData.js`：持有列表与详情响应的纯数据合并。
- `src/services/blablalinkSession.js`：浏览器登录、`game_token` 等待和 Cookie 会话收集。
- `src/services/accountArea.js`：自动区域识别、候选区域验证和批次安全回填。
- `src/services/accountCharacterData.js`：单账号角色采集服务。
- `src/services/crawlSafety.js`：抓取任务去重、冷却和持久化轻量熔断。
- `src/utils/crawlValidation.js`：异常空数据判断与有界重试。
- `src/components/app/hooks/useCrawler.js`：只负责页面流程编排。
